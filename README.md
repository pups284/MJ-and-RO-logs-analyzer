# 🎮 Majestic Log Analyzer

**Локальный анализатор логов для лаунчера Majestic RP / Россия Онлайн**

Автоматически находит типовые проблемы игроков в `main.log`, `client.log`,
`patcher.log` — и подсказывает, что ответить.

## ✨ Возможности

- 🔍 **Автоматический анализ** — прогоняет логи через набор правил и сразу
  показывает, что нашёл: ошибку, предупреждение или просто замечание.
- 📂 **Загрузка логов** — диалогом, drag-and-drop в любое место окна или
  напрямую из Discord (свой бот, скачивает вложения сообщения).
- 🧩 **Редактор с подсветкой** — открывает лог целиком, прыгает к месту
  найденной сигнатуры, подсвечивает её, показывает миникарту справа,
  поддерживает Ctrl+F и нумерацию строк.
- ➕ **Создание правил из выделения** — нашли новую ошибку в редакторе?
  Выделите строку, нажмите «Создать правило из выделения» — оно сразу
  применится.
- 🚫 **Исключения** — «ложное срабатывание» по точной сигнатуре или
  отдельная вкладка «Скрытые» для уже отфильтрованных находок.
- 🧠 **Учёт контекста** — знает, откуда лог (`main` / `client` / `patcher`),
  определяет платформу (Steam / Epic / Rockstar), проект (Россия Онлайн
  или Majestic RP) и путь до папки игры.
- 🔢 **Умный счётчик дубликатов** — правило `Duplicate weapon item`
  ожидает **8** вхождений для России Онлайн и **31** для Majestic,
  отличает редукс от нормы.

## 🚀 Быстрый старт

### 1. Клонировать и поставить зависимости

```bash
git clone <URL_репозитория>
cd Logs_analyzer

python -m venv .venv
.venv\Scripts\activate           # Windows
# source .venv/bin/activate      # Linux / macOS

pip install -r requirements.txt
```

### 2. Запустить

```bash
python main.py
```

или

```bash
python -m majestic_log_analyzer
```

## 📦 Сборка `.exe`

В проекте есть готовый `build.spec` для PyInstaller и скрипты `build.bat` /
`build.sh`.

### Windows

```bat
build.bat
```

Готовый дистрибутив появится в `dist\Majestic Log Analyzer\`. Переносить
нужно **всю папку** — рядом с `.exe` лежит `_internal` с библиотеками Qt.

### Linux / macOS

```bash
./build.sh
```

> ⚠️ **Про размер и альтернативы.**
> PyInstaller-сборка весит 120–160 МБ из-за Qt. Если это критично — есть
> `dist-nuitka/` (Nuitka собирает компактнее и стартует быстрее, но дольше).
> Переписывать на C++/Rust **не нужно** — выигрыш не оправдает затрат.

## 💾 Данные пользователя

При первом запуске рядом с приложением создаётся папка `data/`:

| Файл              | Что внутри                                              |
| ----------------- | ------------------------------------------------------- |
| `data/rules.json` | список правил (создаётся из `bundled_rules.json`)       |
| `data/notes.json` | примечания и исключения                                 |
| `data/ui.json`    | настройки вида (видимость колонок)                      |
| `data/settings.json` | сохранённый токен бота Discord                       |

Всё это можно редактировать как в приложении, так и вручную —
изменения подхватятся при следующем запуске.

## 🧩 Как это работает

1. **Загрузка логов.** Пользователь тащит `.log` в окно, выбирает файлы
   диалогом или импортирует из Discord. Каждому файлу определяется тип
   (`main`, `client`, `patcher`, …) и собираются метаданные — платформа,
   проект, путь до игры.
2. **Анализ последней сессии.** Для `main.log` регион ограничивается
   последним маркером `(startup)` — программа знает, что старые ошибки
   в логе неактуальны.
3. **Матчинг правил.** Каждое правило — это набор `all_of` / `any_of` /
   `none_of` подстрок, опциональный `block_pattern` или `custom_check`.
   Поиск идёт снизу вверх (последнее вхождение в сессии важнее).
4. **Метаданные.** В `main.log` ищется `gtaPlatform` и `gtaPath`. В
   `client.log` — `Game path` и `Connect id: ro<N>/ru<N>` (для правил,
   зависящих от проекта).
5. **Результат.** Находки попадают в таблицу, каждая со своим цветом по
   важности. В правой панели — контекст, объяснение и подсказка, что
   ответить игроку.

## 🛠️ Разработка

- **Python 3.10+**, `PySide6`.
- Правила и заметки — обычные JSON-файлы, легко править и передавать
  коллегам.
- Тема оформления (`style.py`) — один QSS-словарь, его удобно
  раскомментировать/подменить.

## 🐞 Известные нюансы

- **Ошибки не находятся, хотя строки в логе есть.** Проверьте, что файл
  лежит в **последней** сессии. Для `main.log` это регион после последнего
  `(startup)` — старые записи игнорируются специально.
- **Сигнатуры слишком разные.** В `normalization.py` есть список регексов,
  которые схлопывают таймстемпы, UUID и адреса. Если нужен свой вариант —
  добавьте туда правило.
- **`.exe` слишком большой.** Так и должно быть: Qt тянет за собой свои
  библиотеки. Соберите через Nuitka или откажитесь от некоторых Qt-модулей
  в `build.spec` (`EXCLUDES`).
